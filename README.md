# Learning Task-Specific Antibody Representations via Function-Aware Masking

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Python 3.10+](https://img.shields.io/badge/python-3.10%2B-blue.svg)](https://www.python.org/)

Does *where* you mask residues during masked-language-model (MLM) pretraining of
an antibody language model change *what the model learns* and *how well it
transfers* to downstream antibody tasks?

This repository contains the masking framework and training pipeline behind that
question. We train RoFormer / [AntiBERTa2](https://huggingface.co/alchemab/antiberta2)-architecture
models **from scratch** on ~500K heavy-chain (VH) sequences from the
[Observed Antibody Space](https://opig.stats.ox.ac.uk/webapps/oas/) (OAS),
varying **only the masking strategy**, and compare the resulting models under
identical compute and evaluation conditions.

Every strategy spends the same BERT-standard **15% masking budget** with the
same 80/10/10 (mask / random / keep) corruption split — they differ only in
*which* positions they select. A `uniform` baseline masks at random; the other
strategies bias the mask toward biologically meaningful positions using soft,
per-residue priors.


| Strategy        | Biases the mask toward …                                       | Needs               |
| --------------- | -------------------------------------------------------------- | ------------------- |
| `uniform`       | random positions (baseline)                                    | sequence only       |
| `cdr`           | CDR1 / CDR2 / CDR3 loop residues                               | CDR annotations     |
| `span`          | contiguous spans (SpanBERT-style)                              | sequence only       |
| `structure`     | 3D-spatial neighborhoods (IgFold / ESM2 contact-map kNN)       | structure sidecar   |
| `interface`     | predicted paratope (antigen-contacting) residues               | paratope sidecar    |
| `germline`      | somatic-hypermutation sites (residues differing from germline) | germline sidecar    |
| `intersection`  | the product of two priors (e.g. mutated **and** binding-site)  | ≥2 sidecars         |
| `multispecific` | paired VH+VL paratope / shared-light / VH–VL interface         | paired data         |
| `hybrid`        | a stochastic mixture of the above, with an optional curriculum | sub-strategy inputs |


`uniform`, `cdr`, and `span` are **self-contained** (they need only the sequence
and its CDR annotations, both present in the OAS data). The remaining strategies
consume precomputed per-residue **metadata sidecars** (`.pt` files) generated by
the scripts under [scripts/](scripts/) — see [Data](#data).

## Installation

```bash
conda create -n abmlm python=3.10 -y && conda activate abmlm
pip install -r requirements.txt
```

The tokenizer (`alchemab/antiberta2`, a 28-token per-amino-acid RoFormer
tokenizer) is downloaded from the Hugging Face Hub on first use and requires
[`rjieba`](https://pypi.org/project/rjieba/) (pulled in by `requirements.txt`).

## Quickstart (CPU-only smoke test)

A tiny, self-contained demo trains a small (~4.8M-param) model for 50 steps on a
bundled 553-sequence sample of OAS VH data — exercising the full
**masking → training → checkpoint → evaluation** loop with no large downloads.
It runs on a CPU in a few minutes (seconds on a GPU) and is a smoke test of the
pipeline, not a useful model:

```bash
# 1. Train a small model with CDR-biased masking on the bundled sample
python scripts/train.py --config configs/demo.yaml
#    → writes models/checkpoints/demo/final/

# 2. Score the checkpoint with the shipped zero-shot metrics
python scripts/evaluate.py \
    --checkpoint models/checkpoints/demo/final \
    --data data/sample/oas_vh_demo.jsonl \
    --device cpu --max-seqs 50
```

Edit `configs/demo.yaml` and change `masking.strategy` to `uniform` or `span` to
see other self-contained strategies on the same sample.

## Running the tests

The masking strategies ship with self-contained unit tests (synthetic tensors,
no data downloads):

```bash
pytest tests/          # 117 tests covering span / cdr / germline / interface /
                       # structure / multispecific / hybrid masking
```

## Repository layout

```
masking/        Pluggable masking-strategy package — the core contribution.
                base.py (registry + BERT corruption), collator.py, and one
                module per strategy (uniform, cdr, span, structure, interface,
                germline, intersection, multispecific, hybrid).
models/         RoFormer model factory (small / medium / full sizes).
training/       HuggingFace-Trainer wrapper: typed config, training loop,
                hybrid-curriculum callback.
data/           Dataset + on-the-fly tokenization, OAS download & preprocessing
                (single-chain and paired), and the bundled demo sample/.
evaluation/     Zero-shot metrics shipped here: MLM accuracy/perplexity under a
                uniform reference mask, and pseudo-log-likelihood (PLL).
utils/          Tokenizer, seeding, CDR annotation, JSONL I/O.
scripts/        CLI entry points: train.py, evaluate.py, and the data-prep
                pipeline (download / annotate / compute label sidecars).
configs/        One YAML per masking strategy (the experiment matrix) plus the
                runnable demo.yaml.
tests/          Unit tests for the masking strategies.
```

## Masking strategies

Each strategy is a subclass of `masking.base.BaseMaskingStrategy` registered
under a string name. The training loop and collator look strategies up by name,
so they are fully interchangeable. Adding a new one is three steps:

```python
# masking/my_strategy.py
import torch
from masking.base import BaseMaskingStrategy, register_strategy

@register_strategy("my_strategy")
class MyStrategy(BaseMaskingStrategy):
    def select_mask_positions(self, input_ids, special_tokens_mask, metadata=None):
        # Return a (seq_len,) bool tensor: True = mask this position.
        # Never select special tokens. Aim for ~mask_prob of maskable positions.
        ...
```

Import it in `masking/__init__.py`, then reference `strategy: "my_strategy"` in a
config. The base class handles the 80/10/10 mask/random/keep corruption and the
label construction; strategies only decide *which positions* to select.
Data-dependent strategies fall back to uniform masking (with a warning) when
their metadata is absent, so they never hard-fail.

## Training at scale

The demo uses the `small` model; the paper experiments use `medium` (12 layers,
512 hidden, ~50M params) trained for **125,000 steps** under matched compute. The
per-strategy configs are in [configs/](configs/) and exposed as flags on
`train.py`:

```bash
# Train one or more models sequentially (logs → logs/<name>.log)
python scripts/train.py --uniform --cdr --span --structure --interface --germline
```

Training at this scale requires the full corpus and (for the biologically
informed strategies) the metadata sidecars described below.

## Data

The bundled `data/sample/oas_vh_demo.jsonl` (553 sequences) is all you need for
the demo and tests. The **full corpus, metadata sidecars, and trained
checkpoints are far too large to host on GitHub** and are not included; rebuild
them with the shipped scripts:

```bash
# Pretraining corpus: ~497K OAS human VH sequences  → data/processed/oas_vh_500k.jsonl  (~124 MB)
python scripts/download_data.py --config configs/medium.yaml

# (Optional) re-annotate CDRs with ANARCI; OAS sequences already carry CDR fields
python scripts/annotate_cdrs.py --input data/processed/oas_vh_500k.jsonl \
    --output data/processed/oas_vh_500k.jsonl --anarci-fallback

# Metadata sidecars for the advanced strategies (each is a torch-saved
# list[dict|None] aligned 1:1 with the corpus):
python scripts/compute_paratope_labels.py \
    --input data/processed/oas_vh_500k.jsonl \
    --output data/structures/oas_vh_500k_paratope.pt          # interface masking (~353 MB)
python scripts/compute_germline_labels.py \
    --input data/processed/oas_vh_500k.jsonl \
    --output data/structures/oas_vh_500k_germline.pt          # germline masking (~353 MB)
python scripts/predict_structures_igfold.py \
    --input data/processed/oas_vh_500k.jsonl \
    --output data/structures/oas_vh_500k_igfold.pt            # structure masking (~3.7 GB)
```


| Artifact                      | Approx. size    | Needed for                            |
| ----------------------------- | --------------- | ------------------------------------- |
| `oas_vh_500k.jsonl` (corpus)  | 124 MB          | all training                          |
| `*_paratope.pt`               | 353 MB          | `interface`, `intersection`, `hybrid` |
| `*_germline.pt`               | 353 MB          | `germline`, `intersection`, `hybrid`  |
| `*_igfold.pt` (structure kNN) | 3.7 GB          | `structure`, `hybrid`                 |
| paired corpus + sidecars      | 0.3–0.7 GB each | `multispecific`, `hybrid_paired`      |


Computing the structure sidecar additionally requires [IgFold](https://github.com/Graylab/IgFold);
CDR re-annotation requires [ANARCI](https://github.com/oxpig/ANARCI). Neither is
needed for the demo, the tests, or `uniform` / `cdr` / `span` training.

## Evaluation

This release ships the two lightweight, dependency-free **zero-shot** metrics
used to compare strategies on equal footing (`scripts/evaluate.py`):

- **MLM accuracy & perplexity** under a *uniform reference mask* — every model is
scored on the same masking distribution regardless of how it was trained —
with a framework / CDR / CDR3 breakdown when CDR labels are present.
- **Pseudo-log-likelihood (PLL)**, the standard zero-shot protein-LM fitness
score.

The full benchmark suite from the paper (CDR infilling, AB-Bind mutation-effect
correlation, attention analysis, and supervised downstream probes for paratope
prediction, contact maps, structure, and developability) is maintained in the
research repository and omitted here to keep this codebase focused on the
masking method.
